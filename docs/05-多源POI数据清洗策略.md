# 多源 POI 数据清洗策略

> 交付文档 ③（docs/01 §8）。覆盖 POI 数据全链路：**多源采集 → 清洗归一 →
> 覆盖判定（三级漏斗）→ 评分**。实现：`backend/app/poi/service.py`（采集与清洗，
> 纯函数 + 注入 Provider）、`backend/app/coverage/funnel.py`（判定与评分）、
> 类目映射 `data/config/poi_taxonomy.json`。

---

## 1. "多源"的定义与类目映射

本项目 POI 的"多源"是**检索源多样性**：四大民生类目各自映射独立的百度检索
关键词与白名单，同一物理设施可能被不同关键词/不同页召回——去重与归一是清洗
的核心动因。

类目映射表由 `data/config/poi_taxonomy.json` 驱动（非硬编码；文件缺失/损坏时
回退内置默认，启动不阻断）：

| key | label | 检索词 queries | 白名单正则 filter_pattern |
|-----|-------|--------------|--------------------------|
| medical | 医疗（药店） | 药店 | `药` |
| education | 教育（小学） | 小学、学校 | `小学\|九年一贯制` |
| shopping | 购物（菜市场） | 菜市场 | `菜市场\|农贸市场` |
| elderly | 养老 | 养老院 | `养老` |

education 用双检索词的原因（BF-010，2026-10-09 实测杭州和宁文华府）：v3 周边检索
按分词索引匹配，**"实验小学"复合词不被 query=小学/实验小学 召回**——该类学校主体
POI 完全缺席，仅"学校"能召回其门禁 POI（如"杭州市安吉路新文实验小学西门"）；同时
"学校"还召回 query=小学 漏掉的**九年一贯制学校**（含小学部），由白名单 tag 分支
`九年一贯制` 收编、纯中学仍被剔除。多一词 = +1 次逻辑调用，换教育类目召回完整性。

**口径声明（重要）**：检索词 + 白名单是**窄口径高精度**取舍——保证命中的确实是
目标业态（评分的分子不作弊），代价是召回下限（如个体便民菜店不叫"菜市场"则不
计入）。实测影响见 docs/07 §5.3（两社区 shopping 类命中均偏少、盲区大面积报缺）
——这是**口径真实**而非数据错误，报告显式声明，规划者可据此扩类目表（改 JSON
零改码）。

## 2. 采集：翻页聚合与失败隔离

`Provider.search_pois` 单次逻辑调用内部完成全部翻页（`mapapi/baidu/client.py`）：

- 圆形区域检索 `/place/v3/around`，半径 `poi_search_radius_m = 1300`（覆盖
  15 min 步行圈 ~1.1 km + 余量），`radius_limit=true` 硬约束（radius 本身只是
  召回权重）；
- 分页 `page_size=20 × max_pages=3`（v3 契约 page_num ∈ {0,1,2}，越界页**静默
  返回空**——BF-005 实测，故短页即停 + 配置层强制范围校验），单类目召回上限
  60 条；
- 无 `uid` 的记录直接丢弃（不可去重的数据不可信）；
- 类目内多检索词顺序检索后合并（教育 = 小学 + 学校），跨词重复由清洗管道
  uid 去重收口——与真实百度"学校"也能召回普通小学的行为对齐；
- 四大类目 `asyncio.gather` 并发检索；
- **失败隔离**：单类目 `MapApiError` 不拖垮分析——记 `poi:<key>:unavailable`
  降级标记，该类不计入综合评分与盲区判定（BF-007：检索失败 ≠ 该类设施为零）。

## 3. 清洗管道：四步纯函数链

`clean_records(records, spec, center, dedup_m)`（纯函数，毫秒级，全单测）：

```text
原始记录（≤60/类 × 检索词数）
  ① 白名单过滤：re.search(filter_pattern, name + " " + tag)
     —— 拼接匹配名与分类标签，"医药公司/批发市场/纯中学"等噪音在此剔除
  ② uid 去重：同 uid 只留一条（同一数据源重复暴露，跨检索词合并的收口点）
  ③ 同名聚类去重：同名 + haversine < poi_dedup_distance_m(30 m) → 保留首个
     —— 连锁分店同城多名、多源交叉召回的典型形态
  ④ 附属 POI 坍缩：tag ∈ {出入口, 校内设施} 的门禁/楼栋条目按"主体名"分组
     （剥离"-南门"/"西门"/"教学楼-3幢"后缀）——主体在场则剔除附属（同校
     只计一次），主体缺席保留最近一个附属作为该校代表（BF-010：实验小学类
     校名在 v3 索引里只有门禁 POI 可被召回，附属是唯一线索）
  ⑤ 归一输出：回填 category = spec.key、计算到中心直线距离、按距离升序
```

去重键选择依据：**uid 是源内唯一键但跨查询不稳定；"同名 + 30 m"是业务语义键**
（同一家药房在两次检索中位置漂移 < 30 m 属正常坐标抖动）。回放快照内置构造
样本逐项验证该管道：`demo-med-001-dup`（同名 30 m 内重复）、`demo-edu-noise`
（"中关村中学"混入小学查询，白名单剔除）、`demo-med-far`（超出检索半径，采集层
剔除）、`demo-edu-004`（"中关村实验小学西门"，主体缺席保留门禁代表）、
`demo-edu-005`（九年一贯制，tag 命中保留）、`demo-edu-002-gate`（同校门禁，
主体在场坍缩剔除）。

## 4. 覆盖判定：三级漏斗（POI 数据的消费端）

每条设施判"15 min 步行可达否"，判定成本递增、精确度递增（`coverage/funnel.py`）：

| 级 | 方法 | 判据 | confidence | API 成本 |
|----|------|------|-----------|---------|
| 1 几何粗筛 | POLYGON | 点在阈值级等时圈多边形外 → 圈外终判 | 1.0 | 0 |
| 2 时间场插值 | FIELD | 圈内点用等时圈时间场插值耗时 t̂ 与阈值比较 | 0.8 | 0 |
| 3 边缘带实测 | MATRIX / WALKING | t̂ ∈ 阈值 ±2 min（`coverage_edge_band_min`）的设施批量矩阵定论 | 1.0 | ≤30 条 1~2 批 |

细节纪律：

- **边缘带队列排序**：插值不可用（blocked 方向）者优先、其余按 |t̂ − 阈值| 升序，
  上限 `coverage_matrix_verify_limit = 30`——最可疑的先实测，截断不引入方向偏差；
- blocked 方向的点**保守判圈外**且 confidence 减半（BF-008：插值不可用不得冒充
  可达结论）；
- 矩阵失败 → 降级链第二级逐条 `walking_route` 实测（仍为实测口径，flag
  `coverage:matrix:fallback-walking`）；预算不足整层跳过 → 保留插值判定
  （`coverage:matrix:unavailable`）；
- **方法透明**：每条设施的 `method` 字段（POLYGON/FIELD/MATRIX/WALKING）随报告
  透出——判定口径可审计，不装作全是实测。

实测漏斗分布（docs/07）：交道口 19 条设施 = 15 POLYGON 圈外 + 3 FIELD 圈内 +
1 MATRIX 边缘带实测；回龙观 7 条 = 5 POLYGON + 2 FIELD、0 边缘带。**API 只花在
真正模糊的地方**。

## 5. 评分模型

单类目得分（`models/coverage.py` 注释即公式文档）：

```text
score = 100 × ( 0.6 × 覆盖率 + 0.4 × min(1, reachable / 5) )
覆盖率 = reachable / total；sufficient_count = 5
```

- **覆盖率**（60%）：圈内设施占比，衡量"存量设施的可达性"；
- **充足度**（40%）：至少 5 个的饱和曲线，衡量"设施数量是否够用"——只有 1 个
  药店即使 100% 可达也不该得高分（单点故障风险）；
- 检索失败类目不参与；综合评分 = 有效类目等权平均。

**诚实口径**：total 以**窄口径检索的召回**为分母——它衡量的是"目标业态设施的
可达结构"，不是"该社区没有任何医疗资源"。口径声明随报告输出。
