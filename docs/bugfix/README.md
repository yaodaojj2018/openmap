# Bug 修复归档

重要 Bug 修复的过程与结果归档于此（规则定义见根目录 `CLAUDE.md`「Bug 修复归档」）。
目的：根因可追溯、复发可对照、评审可查证。

## 归档范围

- ✅ 影响**功能正确性 / 数据准确性 / 触发外部告警**，且需要根因分析才能修复的问题
- ❌ 不归档：样式调整、文案 typo、开发环境踩坑（后者记入 `CLAUDE.md` 环境事实表）
- 📌 **归档前置条件**：修复必须附带回归测试（`@pytest.mark.regression` + docstring
  注明 BF 编号），CI 用 `scripts/check_bugfix_regression.py` 强制索引表 ↔ 测试引用
  双向一致（规则详见 `docs/regression-ci.md` §6）。AI 生成的回归用例，断言与边界
  条件须对照本档"验证结果"的复现数据人工核对。
- 📤 **退役规则**：回归测试默认永不退役，仅「契约废弃 / 路径删除」两条白名单可退
  （数值随契约调整、假回归均属**修订**而非退役）；退役 = 索引表状态标
  `已退役（YYYY-MM-DD）`（不删行）+ 档案追加「退役记录」+ 移除 regression 标记，
  一致性检查对已退役条目免检。条款与流程详见 `docs/regression-ci.md` §6.1。

## 文件命名与模板

文件名：`YYYY-MM-DD-<slug>.md`（日期 = 修复提交当日）。新建条目须在下表登记。

索引表「状态」列：`现役`（默认）/ `已退役（YYYY-MM-DD）`——退役不删行、不删档。

```markdown
# BF-XXX 标题

- 日期：YYYY-MM-DD 　提交：<hash> 　影响模块：<模块/文件>

## 现象
用户或测试可观察到的症状（含报错原文、监控/短信告警原文）。

## 根因分析
从现象到根因的推理链；写清"怎么定位的"，不只写"是什么"。

## 修复方案
改动点列表（文件级），设计取舍与理由。

## 验证结果
修复后实际跑出的验证输出/数据（禁止无输出的"已验证"）。

## 影响范围与注意事项
波及的调用方、配置迁移要求、复发信号与预防；**必填**回归测试节点 ID
（`@pytest.mark.regression`，docstring 注明 BF 编号，CI 强制校验）。
```

退役时在档案末尾追加：

```markdown
## 退役记录（如发生）

- 日期：YYYY-MM-DD 　提交：<hash> 　条款：契约废弃 / 路径删除
- 证据：<官方公告链接 / 删除 diff 的提交> 　替代防线：<新契约的回归测试 / 无>
```
