# Bug 修复归档

重要 Bug 修复的过程与结果归档于此（规则定义见根目录 `CLAUDE.md`「Bug 修复归档」）。
目的：根因可追溯、复发可对照、评审可查证。

## 归档范围

- ✅ 影响**功能正确性 / 数据准确性 / 触发外部告警**，且需要根因分析才能修复的问题
- ❌ 不归档：样式调整、文案 typo、开发环境踩坑（后者记入 `CLAUDE.md` 环境事实表）

## 文件命名与模板

文件名：`YYYY-MM-DD-<slug>.md`（日期 = 修复提交当日）。新建条目须在下表登记。

```markdown
# BF-XXX 标题

- 日期：YYYY-MM-DD 　提交：<hash> 　影响模块：<模块/文件>

## 现象
用户或测试可观察到的症状（含报错原文、监控/短信告警原文）。

## 根因分析
从现象到根因的推理链；写清"怎么定位的"，不只写"是什么"。

## 修复方案
改动点列表（文件级），设计取舍与理由。

## 验证结果
修复后实际跑出的验证输出/数据（禁止无输出的"已验证"）。

## 影响范围与注意事项
波及的调用方、配置迁移要求、复发信号与预防（如回归测试编号）。
```
