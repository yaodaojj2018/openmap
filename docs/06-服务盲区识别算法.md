# 服务盲区识别算法

> 交付文档 ④（docs/01 §8）。对应命题硬指标："标注 1 公里内缺少菜市场/药店/小学
> 的服务盲区"。实现：`backend/app/blindspot/grid.py`（单模块纯函数），模型
> `models/blindspot.py`。**全本地计算，零 API 成本，<1 s**。

---

## 1. 口径声明（先于算法）

- **判定口径 = 栅格中心到最近设施的直线距离 > 1 km**（命题字面："1 公里内缺少"）；
- 路网口径（步行可达性判定）是**声明未实现的可选增强**——模型注释显式标注
  （`models/blindspot.py`："路网测时口径的差异为文档声明的可选增强，不在本模型
  中"）。两个口径的差异界：直线 1 km ≈ 路网 1.3 km（绕行系数），规划者跨界比对
  时须知此换算；
- 选择直线的理由：① 命题字面口径，评审零歧义；② 与等时圈（路网口径）互补——
  等时圈回答"从中心出发能到哪"，盲区回答"这张网上哪里离设施太远"，两套几何
  各司其职。
- **盲区独立于等时圈（双口径声明）**：盲区研究区是中心点 1.5 km 见方的**规则方形**，
  与路网约束下**不规则**的等时圈边界不重合，灰色区域**落在等时圈之外属正常**——
  两者是并列的双口径，不是"圈内子集"关系。前端报告面板（`ReportPanel` 盲区标题）
  已显式声明"独立于 15 分钟等时圈的 1 公里直线距离服务盲区"。

## 2. 算法流程（`compute_blindspot`）

```text
① 栅格化：中心点 1.5 km × 1.5 km 研究区（blindspot_extent_m=1500），
   100 m 格（blindspot_cell_m=100）→ 15×15 = 225 格
   （格心在米制局部平面布设：经度方向 cos(lat) 收缩，core/coords.local_delta_m）
② 向量化最近邻：三类设施（药店/小学/菜市场，blindspot_types）分别投影建
   cKDTree，一次 query 求 225 个格心的最近设施直线距离（向量化，毫秒级）
③ 缺失判定：距离 > blindspot_threshold_m(1000 m) 的格标记缺失该类；
   记录 worst_distance_m（缺失格中最远的距离，衡量严重程度）
④ 聚类平滑：缺失格 → shapely box → unary_union → buffer(50 m)
   （buffer ≥ 格角间隙 √2/2×100 ≈ 70.7 m 的一半，对角相邻格因此融合——
   8 邻接语义靠几何实现而非显式图遍历）；多边形在米制空间构建（缓冲各向
   同性），仅最终顶点经 offset_lnglat 转回 BD09
⑤ 严重度分级：每格累计缺失类数 severity ∈ {0,1,2,3}；
   severe_cells = 缺失 ≥2 类的格数（复合盲区 = 规划最优先）
```

## 3. 语义纪律（哪些数据有资格进判定）

`types` 由编排层注入：**只含成功完成检索的类目**（`pipeline.py`）——

- 检索失败/用户未选的类目**不参与判定**（其设施列表为空会被误判"全域缺失"——
  BF-007：数据缺失 ≠ 事实结论）；
- 检索成功但零命中**合法地全域缺失**：这是窄口径检索的真实结论（该业态在研究
  区内确实没有以目标关键词命名的设施），如实输出。

实测例证（docs/07）：回龙观 shopping 类检索成功但 0 命中 → 225 格全域缺失；
education 类 3 所小学集中西侧 → 7 格缺失且与 shopping 缺失叠加（severe_cells=7）。
两社区 medical 均 0 缺失格——药店密度足够，算法没有制造假警报。

## 4. 输出契约

`BlindspotResult`：`{types: [{type_key, label, missing_cells, worst_distance_m,
polygons(GeoJSON BD09)}], grid_side, threshold_m, max_severity, severe_cells}`。
前端 `BlindspotLayer` 灰色多边形渲染 + 缺失类型标签；复合盲区（severity ≥2）
以更深灰阶强调。

## 5. 设计取舍

| 选择 | 理由 |
|------|------|
| 栅格 100 m（225 格）而非更细 | 命题精度（1 km 判定）下更细只增加噪声；225 格 cKDTree 向量化 <10 ms |
| 1.5 km 研究区 | 覆盖 1 km 判定半径 + 边缘设施影响域，且与等时圈采样范围（1.2 km）衔接 |
| cKDTree 而非逐格循环 | 225 格 × 3 类向量化一次查询——"能本地算不调 API"铁律的展示点 |
| buffer(50 m) 平滑 | 消除栅格锯齿使多边形可读；融合对角邻接（8 邻接语义） |
| 零 API 兜底 | 盲区计算在配额耗尽/矩阵降级时仍完整产出——报告永不缺这一节 |

## 6. 非居住用地语义纪律与正向掩膜 + 工业园负向修正

> 状态：**已实现**。本节固化「盲区判定只针对居住用地」的口径决策与方案（正向掩膜），
> 以及「工业园被误判成盲区」的针对性负向修正。实现：`grid.py`（居住掩膜 + 工业园
> 负向）、`pipeline.py`（编排检索与降级）、`poi/service.py`（用地 POI 检索与去重）。

### 6.1 为什么需要掩膜：假警报来源

现算法（§2）把中心点 1.5km×1.5km **整块方形**无差别栅格化，只问「格心到最近设施
直线距离 > 1km 吗」，不区分格内是住宅、公园、湖泊、道路还是山体。因此非居住用地
会被误标「缺教育/缺菜市场/缺药店」——这些用地无居民、无服务需求，不是「服务盲区」，
属于**假警报**。

实测例证（杭州城北万象城）：北部玉湖公园（公园+湖泊）被划入「缺教育」，但该地无
居住人口，标记不成立。这与 §3「数据缺失 ≠ 事实结论」同源——此处是「用地语义缺失
被当成缺口事实」。

### 6.2 口径：只对居住用地判盲区

- **盲区 = 居住用地覆盖格内，距最近设施直线距离 > 1km 的栅格**；
- 非居住用地（公园/水域/道路/铁路/山体/工业/公用设施等）**默认不判盲区**，不计入
  `missing_cells` 与 `severe_cells`；
- 命题字面「1 公里内缺少…服务盲区」暗含「有居民却缺服务」，本口径是对命题的直接
  实现，而非额外裁剪。

### 6.3 为什么正向识别居住，而非负向枚举非居住

| 维度 | 负向（枚举非居住再扣） | 正向（识别居住再判）✅ 采用 |
|------|------|------|
| 枚举目标 | 无界（总能漏一类） | 有界（居住是单一自洽类） |
| 关键词实测 | 公园/湖泊/绿地/大学命中稀疏（两地多为 0）、河/山纯噪声 | 小区/住宅/楼盘两地均打满 40 且几乎全为真实小区 |
| 面状地物 | 玉湖公园在「公园」检索中未出现，扣不到 | 无需处理（非小区即排除） |
| 无 POI 用地（道路/铁路/高压线） | 无法枚举 | 自动排除 |
| 风险方向 | 漏枚举 → 假警报 | 漏识别居住 → 漏报真盲区 |

实测数据（2026-10-11，城北万象城 / 嘉绿景苑两坐标，radius 1500m、page_size 20、
2 页）：正向「小区/住宅/楼盘」均 40（打满）；负向「湖泊/水库/绿地/大学」均 0，
「河/山」命中为足道店、山核桃工坊等噪声，「公园」城北仅 1（且不含玉湖公园）。

**正向掩膜的已知短板与工业园负向修正**：正向 200m 缓冲会**漫入紧邻的工业园**——城北
万象城这类「居住 + 工业园」交错区里，园区贴着小区的边缘格（距小区 POI <200m）被误判
成居住，又离学校/菜市场 >1km，于是被标成「缺教育」（假警报）。而工业园**不同于**湖泊/
公园，是定义清晰、覆盖密的 POI 类别（2026-10-12 实测城北「工业园」命中 20、「科技园」
16、「产业园」6，「工厂」为「工厂店」噪声弃用）。故加一层**针对性负向修正**：

```
居住格 = (距小区 POI ≤ residential_radius_m) 且 NOT (距工业园/产业园/科技园 POI ≤ industrial_radius_m)
```

负向只作用于「已判居住」的格，天然有界——不会反向吃掉远离小区的真居住区。

### 6.4 算法增补

```text
⑥ 居住覆盖栅格：新增正向 POI 检索（关键词「小区/住宅/楼盘」，配置化），
   清洗后建 cKDTree，求每格心到最近居住 POI 距离 ≤ residential_radius_m
   的格为「居住格」；
⑦ 工业园负向修正：新增负向 POI 检索（关键词「工业园/产业园/科技园」），
   居住格若距最近工业园 POI ≤ industrial_radius_m 则扣除；
   仅「有效居住格」（⑥ 且非 ⑦）参与 §2 ②③④⑤ 的缺失判定与严重度累计
```

- 复用现有 `search_pois` 检索与 uid/同名去重（`poi/service.search_landuse_pois`），
  **无需新增 Provider 方法**（省去回放快照扩展连带成本）；
- 缺失判定、`severe_cells`、`missing_cells` 全部只在有效居住格上计算；
- 检索失败（数据缺失）时**不静默回退**：按 §3 BF-007 纪律，标记
  `residential:unavailable` / `residential:empty` 降级，报告声明「居住用地识别失败/
  为空，盲区按全域研究区口径计算」，而非把缺失冒充成全居住；
- 工业园检索失败/空命中**不降级**：它只是精化层而非结论数据源（空命中 =「该区无
  工业园」是合法结论，不是数据缺失），仅记 warning。

### 6.5 配置化与预算

| 配置项 | 建议默认 | 说明 |
|------|------|------|
| `blindspot_residential_queries` | `["小区","住宅","楼盘"]` | 正向居住关键词 |
| `blindspot_residential_radius_m` | 200 | 格心到最近居住 POI ≤ 此值判居住格（点→面近似半径） |
| `blindspot_industrial_queries` | `["工业园","产业园","科技园"]` | 负向修正关键词 |
| `blindspot_industrial_radius_m` | 300 | 格心到最近工业园 POI ≤ 此值判工业格（园区 > 小区，半径取 1.5× 居住） |
| `blindspot_mask_enabled` | `true` | 掩膜总开关（评审兜底可关） |

新增出站成本 = 正向 3 次 + 负向 3 次 ≤ 6 次检索；实测单次分析约 17 次、硬上限 40，
余量充足，不触碰预算护栏。

### 6.6 残余风险与声明

- 居住 POI 覆盖不到的居住区（城中村/老小区/自建房）可能被漏 → **漏报**真盲区。
  这是「宁可漏报不可假报」的刻意取舍，与 coverage 漏斗 `provisional.in_circle=False`
  的保守取向同源（docs/02 §3.2）；
- 点→面近似半径（`residential_radius_m`=200 / `industrial_radius_m`=300）是启发式取值，
  小区/园区形状不规则时边缘存在误差；如需精化，可用「工业园 POI → 最近小区 POI」的
  距离分布高位分位数标定半径。
