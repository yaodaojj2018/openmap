# 真实社区对比测试报告：紫阳（老城边缘） vs 丁兰（大型居住区）

> 交付文档 ⑤（docs/01 §8："针对特定社区的真实对比测试报告"）。
> 全部数据来自 **2026-10-14 真实百度地图 API 采集**（非回放快照），原始报告固化于
> `data/samples/ziyang.json`、`data/samples/dinglan.json`，采集工具
> `backend/scripts/collect_samples.py` 可复现（见 §8）。

## 1. 测试目的与方法论

- **目的**：① 六类分类体系（医疗/教育/购物/金融/养老/公共服务，docs/02 §3.2）下的
  全链路真实验证（含居住掩膜盲区、边缘带精判）；② **结构敏感性**——用城市肌理迥异的
  两个社区，检验算法输出对路网结构与设施分布的**敏感性**（而非输出千篇一律的圆）；
  ③ 真实预算口径验证（六类分页检索下的调用构成，§6）。
- **方法**：每社区一次完整分析（geocode 解析街道 → 15 min 步行阈值 → 全类目全流程），
  验收标准：任务 completed、`degraded_flags = []`、`http_calls ≤ 35`（docs/02 §3.1.3
  六类预算表口径，见 §6）。
- **环境**：真实 AK（个人认证，免费配额档）；QPS=2 / 突发=2（BF-009 后）；单分析硬上限
  40；批量上限 50 OD/批；POI 检索半径 1300 m；等时圈采样方向 16。

## 4. 结果对比

### 4.1 等时圈几何（实测 ray-spline-v1）

| 指标 | 紫阳 | 丁兰 | 解读 |
|------|--------|--------|------|
| 5 min 圈面积 | 0.154 km² | **0.209 km²** | 小尺度反直觉：大院区内部路网规整通畅，老城边缘受地形与街巷所限反而更小 |
| 15 min 圈面积 | 1.832 km² | **1.895 km²** | 几乎持平——山水约束抑制了老城边缘的路网优势，面积对比不能预设"老城必大" |
| 15/5 min 面积比 | **11.86** | 9.07 | 紫阳内圈被地形压死、外圈沿走廊释放；丁兰匀质扩张 |
| 5 min 圈长宽比 | 0.820 | 0.791 | 两者皆南北向拉伸；紫阳与山—江夹峙下的秋涛路走廊结构一致 |
| 15 min 圈半径变异系数 | **0.242** | 0.124 | 大尺度反转：紫阳边界被山体/铁路/江岸切割锯齿剧烈，丁兰平原正交网格平滑 |
| confidence（5/10/15） | 1.000 / 1.000 / 0.886 | 1.000 / 1.000 / 1.000 | 紫阳 15 min 双法分歧方位加密后如实折算，未虚标 |

几何结论：等时圈形状忠实映射了两个社区的结构差异——面积相近但**形状语言相反**：
小尺度与大尺度锯齿各反转一次（大院之墙 vs 山水切割）。若算法输出的是千篇一律的圆，
这些形状指标应高度相似。

### 4.2 阶段 D 加密（双法仲裁的实测案例）

紫阳 `densified=2`：15 min 圈双法分歧方位补 2 探针（1 次批量矩阵）后一致性收敛至
0.886（未虚高）；丁兰 `densified=0`，零加密成本——**可选精度层只在需要时花钱**。

### 4.4 盲区识别（零 API，15×15 栅格，居住掩膜实测）

| | 紫阳 | 丁兰 |
|---|--------|--------|
| medical（药店） | 0 格缺失 | 0 格缺失 |
| education（小学） | **3 格缺失**（worst 1120 m，边缘型） | 0 格缺失 |
| shopping（菜市场） | **164 格缺失**（检索成功但 0 命中） | **0 格缺失**（桃花湖农贸市场 1.7 min） |
| 复合盲区（≥2 类） | 3 格（max_severity=2） | 0 |

- **居住掩膜（docs/02 §3.3）真实实测**：丁兰 101 格非居住用地（含智慧小镇产业区）被
  排除、46 格工业园负向修正——不把工厂的"缺设施"记成居民的盲区；紫阳排除 61 格
  （山体/行政/商业为主的非居住格）；
- **丁兰三类关键设施零盲区**：丁桥 2005 年规划的净菜市场等公建配套真实兑现（桃花湖
  农贸市场步行 1.7 min）——"规划配套型居住区"的供给模式被算法显影，这正是"体检→规划"
  产品主张的量化落点；
- 紫阳购物 164 格缺失：1300 m 检索半径内无"菜市场|农贸市场"白名单命中——山南新建
  居住带的生鲜供给可能以生鲜超市/便民菜店形态存在而不入白名单（口径 vs 供给的辨析
  见 §5.3）；
- 两社区药店密度均充足（0 缺失格）——算法没有制造假警报。

## 5. 差异归因

1. **自然约束 vs 平原规划 → 等时圈面积**：两社区 15 min 面积几乎持平（1.83 vs
   1.90 km²）——紫阳样点可步行空间被山体与江岸夹峙，老城边缘的路网密度未能兑现为
   面积优势；算法测的是真实结构，而非"老城必大"的先验；
2. **路网形态 → 圈形指标双反转**：小尺度锯齿丁兰 > 紫阳（大院之墙 vs 走廊路网），
   大尺度反转（紫阳山水切割 0.242 vs 丁兰平原网格 0.124）——与两类社区的结构特征
   一一对应；
3. **设施配套模式**：丁兰=规划配套先行（购物/公卫零盲区、社区卫生 2/2 可达）；紫阳=
   老城边缘沿干道集聚（金融 29 家但居住格仅过半可达、购物白名单业态空白 164 格）。

### 5.3 已知口径局限（如实声明，不装作没有）

- **shopping 召回口径**：白名单 `菜市场|农贸市场` 不覆盖生鲜超市/便民菜店——本组恰好
  构成口径的"自然实验"：丁兰命中（农贸市场业态留存）而紫阳 0 命中，提示解读时区分
  "口径空白"与"供给空白"；扩 `data/config/poi_taxonomy.json`（零改码）即可复测紫阳
  真实供给；
- **elderly 两社区 0 命中**：养老院业态本身低密度且检索词单一；
- **education 召回偏少**（丁兰 3 所、1 所圈内）：小学服务半径 ~500 m 的地理事实 +
  白名单过滤，不作为"供给缺失"的断言；
- **单中心点视角**：geocode 街道级落点=街道办驻地（紫阳在秋涛路一带，非十五奎巷坊巷
  核心），同一街道内不同小区结论会平移——产品支持任意点选/地址搜索发起，正是为此。

| 指标 | 目标 | 紫阳 | 丁兰 |
|------|------|--------|--------|
| 出站 HTTP（http_calls） | ≤ 35（硬上限 40） | **32** | **26** |
| 重试（限流退避自愈） | — | 3 | 0 |
| 降级标记 | 无 | `[]` | `[]` |
| 等时圈口径 | 实测 | ray-spline-v1 | ray-spline-v1 |
| 任务状态 | completed | ✅ | ✅ |

**验收线设定依据**：六类口径下高密度城区 POI 检索翻页达 14 页请求（6 首页 + 8 翻页），
本次实测 32/26——低于验收线 35，亦远低于硬预算 40（占用 80%/65%）。依据 docs/02
§3.1.3 六类预算表（POI 14~24、合计 ≈18~32）设定验收线 ≤35；硬上限 40 与"批量不逐条、
能缓存不重发、能本地算（haversine/cKDTree）不调 API"的纪律不变。对照朴素方案
（逐 POI 逐方向路径规划，300+ 次）仍降一个数量级。

调用构成（物理口径，含矩阵 50 OD 分片与重试）：紫阳 = POI 页请求 14 + 矩阵分片 ≈15
（6 逻辑批）+ 限流退避重试 3；丁兰 = POI 14 + 矩阵分片 12（5 逻辑批，0 重试）。

## 7. 结论与规划建议

1. **功能结论**：六类口径全链路（含金融/公共服务、居住掩膜、边缘带精判）在真实 API
   下零降级完成，等时圈/漏斗/盲区三套算法的输出与两个社区的城市结构定性认知吻合
   ——功能正确性（40% 维度）有了真实数据背书；
2. **结构敏感性结论**：核心算法测的是真实路网而非先验套路——同一组形状指标随社区
   结构在不同尺度上翻转方向（小尺度与大尺度锯齿反转、面积优势被地形抵消）；
3. **规划建议（示例，体现产品主张）**：
   - 紫阳：山南秋涛路走廊 164 个居住格购物白名单业态空白——优先以便民菜店/生鲜超市
     业态补建（或先扩口径复测确认真实供给），并复核教育盲区边缘带（worst 1120 m，
     刚过 1000 m 阈值）的设施布点；
   - 丁兰：三类关键设施零盲区 + 公共卫生服务全可达，可作为"15 分钟生活圈配套先行"
     的量化正面案例；短板在金融网点分布（3/12）与教育覆盖（28.0 分）；
4. **工程结论**：真实测试不可被 mock 替代——紫阳 3 次限流退避自愈只有真实并发窗口
   才能触发；验收线与预算口径也只有真实数据才能校准。

## 8. 复现指引

```bash

python3 scripts/collect_samples.py            # 内置两社区（紫阳/丁兰），间隔 20s 冷却并发窗口

```

固化样本结构：`{meta（时间/commit/配置）, report（完整六类分析报告）, derived（几何
派生指标——面积/长宽比/半径变异系数）}`，可直接 diff 对比；亦可用 DEMO_MODE=1 在
回放模式演示同款报告形态（`data/replays/demo.json`）。
